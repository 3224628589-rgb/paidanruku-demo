> 本文档记录当前 Demo 的实现快照和产品后续明确口径，不替代根目录最新稿 [《入库提效三期 拍单入库新》](../../入库提效三期%20拍单入库新.docx)。页面、本文与 Word 有冲突时，先登记冲突并请产品确认，不得默认以当前实现或派生稿覆盖最新稿。逐条对照见 [PRD 对齐交付说明](../design/prd-alignment/README.md)。

## 1. 产品定位

掌店易智能入库是面向医药 O2O 前置仓店员的桌面端工作台。店员从一个具体的**入库任务**进入，利用随货同行单、药品追溯码和系统采购单完成账、票、实的核对。

主流程只有三步：

1. **拍单**：拍摄或上传随货同行单，形成票据和 OCR 依据。
2. **验货**：识别药品追溯码，形成按票据归属的实物品批。
3. **核准**：对异常明细进行采购单、随货单、实物和美团商品资料的核对与决策。

不提供独立“找单”步骤；采购单匹配由系统在核准阶段完成。PC 版不使用设备外框、移动端比例或竖向底部状态条。

## 2. 信息架构和进入规则

### 2.1 任务入口页

首屏为“入库任务”页，包含：

- “新建入库任务”。
- 历史任务列表：任务编号、创建时间、供应商、任务状态、当前步骤、票据数、追溯码数、异常数、更新时间与进入/查看动作。
- 点击任务卡或“进入”恢复该任务对应的票据、扫码和核准状态。

新建任务默认进入拍单，初始状态为“待拍单”。返回任务列表会保留当前任务的实时统计。

### 2.2 三步工作台

- 顶部横向步骤条只显示“返回任务列表、拍单、验货、核准”。
- 未拍票据时，点击验货或核准提示“请先拍摄或上传随货同行单”。
- 已拍票据后可进入验货。
- 未完成扫码时，点击核准提示“请先完成验货扫码”并回到验货。
- 进入核准先展示“正在智能匹配系统单据”，完成后显示核准工作台。

## 3. 数据与状态

### 3.1 四类业务数据

| 数据 | 用途 |
| --- | --- |
| 系统采购单 | 提供平台单号、供应商、商品、数量、批次与状态，是“账”。 |
| 随货同行单 | 拍单后的图片与 OCR 行，是“票”。 |
| 追溯码实物 | 扫码解析出的商品、国药准字、批号、效期和码集合，是“实”。 |
| 美团商品资料 | 提供商品基础资料、价格和图片，辅助人工确认。 |

### 3.2 品批粒度

验货列表以“**票据归属 + 商品批次**”聚合。不同票据中相同商品批次可各自形成一行；同一票据命中同一品批时，追溯码追加到该行。这使拍多张票据后，已录入品批能持续增长，而不是被固定为五行。

核准队列不沿用验货列表的品批聚合粒度。每个已验追溯码生成一张独立商品卡，卡片数量恒为 `1`，并拥有独立核准 ID 和核准状态。同一品批验出 `7` 件时，核准队列必须出现 `7` 张卡；不同品批 `7 + 7 + 2` 件时必须出现 `16` 行。

### 3.3 状态定义

| 状态 | 条件 | 处理 |
| --- | --- | --- |
| 待验货 | 已拍票据行尚无实物匹配 | 保留票据证据，等待扫码。 |
| 待核准 | 数量、批号、名称、规格、准字等异常，或标记破损待采退 | 进入核准队列。 |
| 准入库 | 账、票、实关键字段一致且无破损，或人工核准通过 | 可批量提交入库。 |
| 已入库 | 准入库明细已被提交 | 只读查看。 |

拍单、验货、核准共享同一进度数据；新建任务的四张卡均为 `0`，右侧四段轨道均为空槽。任何页面和任务都不得覆盖或写死进度数字。

待验货保持 OCR 明细行口径：一条仍有未验数量的 OCR 行只计 `1`，卡片数字必须等于待验货明细列表行数，不读取该行采购数量。已验后的待核准、准入库、已入库按追溯码一件一卡计数；提交入库时商品卡从准入库迁移到已入库。三页动态轨道以四个实时卡片数之和为分母。

## 4. 拍单工作台

### 4.1 页面结构

- 左侧/主列：随货同行单高拍仪取景框，画面内有拍照按钮与相册上传入口。
- 主取景框右侧：已拍票据数量、全选、删除所选和单列纵向滚动的票据照片，每行一张。
- 最右侧：Figma 入库进度组件。

取景框必须是拍单页最大视觉主体。票据照片固定为一列纵向滚动，不换成多列照片墙。

### 4.2 操作

| 操作 | 结果 |
| --- | --- |
| 点击拍照 | 锁页执行 OCR、随货单匹配和智能核准；全部成功后新增“拍摄票据 n”并提示“识别成功！”。 |
| 从相册上传 | 仅接收 PNG/JPG、最大 10MB；校验后执行与拍照相同的识别链路。 |
| 勾选票据 | 将图片加入或移出待删除集合；不立即删除。 |
| 全选 / 取消全选 | 同步选择或取消当前全部票据。 |
| 删除所选 | 批量移除所有勾选票据并更新任务统计；缩略图不再提供右上角删除 X。 |
| 点击验货步骤 | 有票据时进入验货；无票据时拦截并提示。 |

## 5. 验货工作台

### 5.1 页面结构

- 左侧：追溯码扫描取景画面、识别成功反馈与“模拟识别”。
- 中部：已录入品批标题、搜索框、已录入码数、全选/删除所选和纵向滚动的品批列表。
- 右侧：Figma 入库进度组件。

品批卡展示商品名、规格、核准标记、国药准字、批号、效期、当前录入码、破损待采退与追溯码数量。搜索支持通用名、准字、批号及追溯码。

### 5.2 识别和排序

1. 点击“模拟识别”生成一组追溯码结果；后续轮次轮流归属不同已拍票据。
2. 同一品批新码追加，新的品批新建卡片。
3. 本轮最后命中的品批冲到列表第 1 位；同轮其他命中按最近顺序紧随其后。
4. 原有品批保持相对顺序并平滑下移，列表自动滚到顶部。
5. 命中卡高亮约 2 秒，本次追溯码高亮约 1 秒，扫描取景框显示成功反馈。

### 5.3 其他操作

- 点击追溯码数量进入编辑：20 位自动校验、应录码蓝色、非应录码黄色；剩最后一码时不可删除。
- 品批卡片支持逐张勾选；“全选”作用于当前搜索结果，“删除所选”按卡片粒度批量删除，并同步移除卡片内全部追溯码。
- 删除最后一个码时，移除品批；随之重算待验货、待核准和准入库。
- 打开“破损待采退”后，该品批强制进入待核准；关闭后重新按匹配结果判定。
- 本期不考虑码上放心未上传追溯码资料的情况；所有有效验货明细均有码上放心资料兜底，不生成无归属商品卡或待核准行。
- 验货商品卡使用三态颜色：明细核准状态 `1-准入库` 为绿色“无需核准”，明细核准状态 `0-待核准` 为黄色“待核准”，入库状态 `1-已入库` 为蓝色“已入库”。
- 已入库追溯码不得再次命中或录入；识别后直接提示“无法录入已入库追溯码”，且不新增数据、不重排列表、不播放命中和进度动效。

验货页只展示轻量核准状态，不展开三方证据或候选替换。

## 6. 核准工作台

### 6.1 页面结构

| 区域 | 内容 |
| --- | --- |
| 左列 | 待核准商品队列、数量、搜索和商品切换。 |
| 中部详情 | 按蓝色入库信息卡、黄色商品资料与 6 图墙、三方数据对比自上而下排列。 |
| 右列 | “提报异常”、四张状态卡与四色分段轨。 |

核准详情以 Figma node `232:5852` 为准：三段同宽同轴，蓝卡和黄卡不得再左右并排压缩。右列以 node `231:5827` 为准。

### 6.2 核准操作

| 操作 | 结果 |
| --- | --- |
| 核准完毕 | 当前明细进入准入库，队列自动切到下一条。 |
| 核准待定 | 当前明细保留待核准清单，但从当前处理队列移出并切到下一条。 |
| 换采购单商品 | 打开候选选择，替换后重新计算对比。 |
| 换随货单商品 | 打开候选选择，替换后重新计算对比。 |
| 编辑追溯码 / 编辑批次 | 保存后更新当前证据与状态。 |
| 提报异常 | Demo 显示“已标记：提报异常”反馈；本轮不定义服务端持久化。 |
| 提交入库 | 将准入库明细移至已入库。 |

## 7. 右侧入库进度组件

### 7.1 视觉和行为

- 拍单、验货、核准使用同一个进度组件；三页从上到下均为“提报异常”、已入库、准入库、待核准、待验货，最右轨道依次为蓝、绿、黄、粉四段。
- 三页进度结构、基础尺寸、缩放比例、数字与轨道比例完全一致；切换步骤只切换主工作区，不改变进度状态。
- 点击卡片或轨道段进入相应页内明细：待验货按“随货单图片 → OCR 行”两级展示；待核准按一张商品卡一行平铺；准入库和已入库按“采购单 → 商品”两级展示。
- 核准决策只出现在当前选中队列项的两枚操作中；“提报异常”是右列唯一新增操作，状态卡内部仍不放决策操作。

### 7.2 状态明细操作

| 页面 | 操作 |
| --- | --- |
| 待验货 | 页码精准、通用名模糊、批准文号精准、只看未验货；勾选/全选/删除所选。 |
| 待核准 | 药品名/准字/异常项并集筛选；查看详情、单条或批量提交准入库；无系统单匹配时拦截。 |
| 准入库 | 采购单、商品、准字筛选；全局/采购单/商品两级勾选；批量回退或提交入库。 |
| 已入库 | 字段同准入库；详情严格只读，只支持返回。 |

### 7.3 动效触发

| 事件 | 目标状态 | 动效 |
| --- | --- | --- |
| 新增票据 | 待验货增加 | 卡片轻弹 + 轨道向右充能发光。 |
| 扫码得到异常 / 一致结果 | 待核准或准入库增加 | 卡片轻弹 + 对应轨道充能发光。 |
| 核准队列：放入准入库 | 准入库增加 | 当前队列卡飞入绿落点 + 卡片轻弹 + 左侧推进充能。 |
| 核准队列：留在待核准 | 数量不变 | 当前队列卡移动到队尾；不触发右侧卡片或轨道发光。 |
| 提交入库 | 已入库增加 | 卡片轻弹 + 左侧推进充能。 |

动画只在实际数量增加时触发。`charging` 和 `bucket-impact` 在约 1.05 秒后清理；步骤切换、列表渲染和读取历史任务不得触发。

## 8. 文案与视觉边界

- 页面只展示完成当前操作需要的信息、数据和命令；不展示业务背景、算法原理或营销说明。
- 不恢复独立找单页、底部大按钮栏、设备边框、移动端照片墙或底部横向四状态条。
- 主工作区优先于装饰、标题和解释；不使用卡片套卡片造成空间浪费。

## 9. 当前 Demo 验收清单

### 任务与拍单

- 首屏可以新建任务和进入历史任务。
- 新任务直接进入拍单；返回入口后任务统计同步。
- 拍照/上传后票据照片位于取景框右侧的单列；通过逐张勾选、全选和“删除所选”批量管理。

### 验货

- 识别结果不受五行限制；多票据可产生多组品批。
- 新命中品批冲到顶部，既有卡片平滑下移。
- 追溯码可查看、删除；破损正确进入待核准；本期不出现无商品资料明细。

### 核准与进度

- 队列、详情、商品资料、三方对比和进度组件在 PC 首屏内有明确分工。
- 蓝卡、黄卡与三方对比按 Figma `232:5852` 上下同轴排列。
- 核准进度组件保留 Figma `231:5827` 的提报异常、四卡和轨道参数，点击状态卡可进入状态明细。
- 仅真实状态增加播放进度动效；动效结束后类名清理，无控制台页面错误。
