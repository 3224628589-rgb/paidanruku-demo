# 核准页：交互与业务逻辑

## 1. 页面目标

核准页集中处理需要人工判断的异常明细。店员应在同一桌面首屏内看到待处理队列、当前商品的账票实证据、美团商品辅助资料和入库进度，并完成决策。

## 2. 进入与离开

| 场景 | 规则 |
| --- | --- |
| 无票据 | 拦截并提示先拍单。 |
| 有票据但无扫码 | 拦截并回到验货，提示先完成验货扫码。 |
| 有扫码数据 | 先显示“正在智能匹配系统单据”，完成后显示核准工作台。 |
| 待核准队列为空 | 可查看状态明细；工作台显示空状态。 |
| 返回验货 | 保留已拍票据、品批和核准决策。 |

## 3. PC 页面结构

```text
┌──────────────────────────── 横向步骤条：返回任务列表 / 拍单 / 验货 / 核准 ────────────────────────────┐
│ ┌──── 待核准队列 ────┐ ┌────────────── 当前核对详情 ───────────────┐ ┌── 入库进度查询 ──┐              │
│ │ 搜索 / 待核准数量  │ │ [蓝色入库信息 + 随货单命中图]              │ │ 提报异常           │              │
│ │ 商品 A              │ │ [黄色商品资料 + 6 张商品图]                │ │ 已入库             │              │
│ │ 商品 B              │ │ [三方数据对比：采购单 / 随货单 / 实物]      │ │ 准入库             │              │
│ │ 商品 C              │ │ 异常字段优先；[展开全部字段]                │ │ 待核准 / 待验货 + 轨道 │           │
│ └────────────────────┘ └──────────────────────────────────────────┘ └──────────────────┘              │
└──────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 布局约束

- 左列只用于队列、搜索、切换和当前队列项的两枚决策图标；不能承载复杂证据。
- 中部按 Figma node `232:5852` 纵向排列蓝卡、黄卡和三方数据对比，三段严格同宽同轴。
- 右列显示“提报异常”、四张状态卡和四色分段轨；准入库卡保留核准通过的动画落点，待核准卡只作为查询入口。

## 4. 数据与核对逻辑

当前明细把以下来源放在一起：

| 来源 | 作用 |
| --- | --- |
| 实物品批 | 当前追溯码、批号、效期、数量，是判断基准。 |
| 系统采购单 | 采购状态、供应商、商品与数量，是“账”。 |
| 随货同行单 | OCR 命中行和局部图，是“票”。 |
| 美团商品 | 商品基础资料、价格、图片，辅助人工确认。 |

默认突出异常字段；“展开全部字段”后显示完整字段对比。候选替换和编辑保存后必须重算当前明细的异常与状态。

## 5. 队列与操作

| 操作 | 结果 |
| --- | --- |
| 搜索或点击队列项 | 切换当前核准明细，更新中部详情。 |
| 选中项“放入准入库” | 当前一件商品卡飞入右侧准入库卡，进入准入库；只迁移 `1`，并自动选择下一条。 |
| 选中项“留在待核准” | 当前队列项保持待核准并移动到队尾；自动选择下一条，四卡数量不变。 |
| 换采购单商品 | 打开全部候选；输入系统单/商品条件并按 Enter 查询，暂选后“确认修改”，再重新核准。 |
| 换随货单商品 | 打开当前任务全部随货单候选；输入票据/商品条件并按 Enter 查询，确认后重新核准。 |
| 编辑追溯码 / 批次 | 追溯码按 20 位自动校验并用蓝黄区分；批次支持实物/随货单/采购单一键填入及批号、效期、生产日期保存。 |
| 提报异常 | Demo 显示“已标记：提报异常”反馈；本轮不定义服务端持久化。 |
| 提交入库 | 准入库页只提交勾选明细；二次确认后复核系统行有效性、生成入库草稿并展示 A/B/C 回执。 |

## 6. 进度与明细入口

- 待核准队列按追溯码逐件展开，一张商品卡只代表 `1` 件；队列行数、左侧“待核准”标题和右侧待核准卡数字必须一致。
- 右侧与拍单、验货使用同一个进度组件，顺序为提报异常、已入库、准入库、待核准、待验货；三页组件结构、尺寸与间距一致。
- 四卡数字与轨道比例始终读取同一份真实任务状态，不允许按页面或任务写死；切换步骤不改变进度展示。
- 点击状态卡/轨道段打开页内明细：待验货按图片/行两级查看，待核准一卡一行，准入库/已入库按采购单/商品两级查看。
- 待核准支持异常项多选并集筛选、单条详情提交与批量提交；未匹配系统单的明细不能进入准入库。
- 准入库支持全局/采购单/商品勾选、批量回退、勾选入库；已入库详情严格只读。
- 核准完毕导致准入库真实增加时，准入库卡弹动且轨道从左侧推进；提交入库同样反馈已入库。
- 三页短屏使用同一缩放比例；提报异常点击后显示明确反馈。

## 7. 验收

- [ ] 无票据或无扫码进入核准均按规则拦截。
- [ ] 进入时出现匹配 loading，随后是队列、详情、进度三列工作台。
- [ ] 蓝卡、黄卡、三方对比自上而下同宽排列；黄卡展示六张商品图，一致值为灰色。
- [ ] 队列切换、候选替换、编辑与异常提报不破坏三列结构。
- [ ] 核准完毕、核准待定和提交入库正确更新明细归属与下一条队列。
- [ ] 三页右侧均显示“提报异常”；四状态卡仍可打开页内明细。
- [ ] 切换拍单、验货、核准时四卡数字、轨道比例和组件几何保持一致。
- [ ] “留在待核准”后当前卡移动到队尾，待核准数量不变且右侧进度不发光。
- [ ] 同品批多件不得合成一张 `Xn` 卡；`7 + 7 + 2` 件必须渲染为 `16` 行待核准商品卡。
