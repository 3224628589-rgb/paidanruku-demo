# 验货页：交互与业务逻辑

## 1. 页面目标

店员通过追溯码扫描把实物转成可核对的品批。验货页要让用户同时感知扫描画面、最近识别结果和可持续增长的品批列表；复杂的账票实差异留给核准页。

## 2. 进入与数据范围

| 场景 | 规则 |
| --- | --- |
| 无票据进入 | 拦截，提示“请先拍摄或上传随货同行单”。 |
| 已有票据进入 | 展示扫码画面、已录入品批和右侧进度组件。 |
| 多票据 | 每张票据拥有独立的品批归属；相同商品/批次在不同票据下可以分别出现。 |
| 离开到核准 | 至少有已识别追溯码；否则提示“请先完成验货扫码”。 |

## 3. PC 页面结构

```text
┌──────────────────────────── 横向步骤条：返回任务列表 / 拍单 / 验货 / 核准 ────────────────────────────┐
│  ┌────────────── 扫码取景 ──────────────┐  ┌──────────── 已录入品批（可滚动）────────────┐  ┌─进度─┐ │
│  │ 商品包装/追溯码画面                  │  │ 搜索框                 已录入 n 码          │  │ 已入库│ │
│  │ 本次识别成功和追溯码反馈             │  │ [最近命中品批：冲顶、高亮]                  │  │ 准入库│ │
│  │                      [模拟识别]      │  │ [既有品批：平滑下移]                        │  │ 待核准│ │
│  └─────────────────────────────────────┘  │ [更多品批 ...]                              │  │ 待验货│ │
│                                             └───────────────────────────────────────────┘  └──────┘ │
└──────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 布局约束

- 扫码画面和品批列表左右并置；品批列表是纵向滚动容器，不设置固定五行高度。
- 右侧进度组件稳定占列，不随品批行数增加而移动。
- 不在本页展示三方数据对比、采购单候选或异常解释。

## 4. 品批模型

品批 key 是“票据归属 + 原始批次事件”。每行包含：

| 字段 | 用途 |
| --- | --- |
| 商品名、规格 | 店员识别实物。 |
| 国药准字、批号、效期 | 核对和后续匹配依据。 |
| 追溯码集合 | 本批次的实物证据，可展开与删除。 |
| 品批卡片选择 | 每张已录入品批卡片可独立勾选；标题区支持全选/取消全选当前筛选结果。 |
| 状态标记 | “无需核准”“待核准”或“已入库”。 |
| 破损待采退 | 破损优先于自动一致判断。 |
| 本次录入 | 显示本轮刚识别到的码。 |

当前 `scopeScanEventToReceipt()` 为模拟扫码事件添加票据归属；生产版必须由服务端保存 receipt id、追溯码唯一性和批次聚合关系。

## 5. 识别、排序和状态

### 5.1 模拟识别

1. 点击“模拟识别”生成一组码事件。
2. 本轮按拍照顺序轮流归属到票据；同票据同品批追加码，不同票据建立独立品批。
3. 系统基于码上放心验货明细计算自动一致、异常和破损状态；本期每条验货明细都有码上放心资料兜底。
4. 本轮最后命中项为视觉主角，移至索引 `0`；同轮其他命中紧随其后。

### 5.2 运动反馈

- 命中卡添加 `just-hit batch-rush-top`，用 `batchRushToTop` 从下方向顶部冲入。
- 已在列表中的卡片根据前后位置使用 FLIP 位移动画，平滑被挤下。
- 命中卡约 2 秒高亮；本次命中的追溯码约 1 秒高亮；之后两类状态类均清理。
- 列表自动滚动到顶部，扫描取景区显示识别成功。

### 5.3 状态判定

| 条件 | 结果 |
| --- | --- |
| 对码核准明细主表：明细核准状态 = `1-准入库` | 绿色卡片，标记“无需核准”。 |
| 对码核准明细主表：明细核准状态 = `0-待核准` | 黄色卡片，标记“待核准”。 |
| 对码核准明细主表：入库状态 = `1-已入库` | 蓝色卡片，标记“已入库”。 |
| 破损待采退开启 | 待核准。 |
| 码上放心资料兜底 | 每条有效扫码都能定位码上放心验货明细，不生成“没有找到商品信息”卡片或待核准行。 |

状态优先判断入库结果；同一品批存在尚未入库的商品卡时，验货列表展示仍需处理部分的状态。已入库追溯码再次被识别时必须在写入、排序和命中动画之前拦截，提示“无法录入已入库追溯码”。

## 6. 次要操作

| 操作 | 结果 |
| --- | --- |
| 搜索 | 按通用名、准字、批号或追溯码过滤品批。 |
| 查看追溯码数量 | 打开该品批完整追溯码列表。 |
| 删除追溯码 | 在编辑草稿中移除码；剩最后一个码时隐藏删除入口，不允许删空。 |
| 删除所选品批 | 二次确认“确定删除？”后，一次删除所有已勾选验货卡片及卡片内追溯码，并重算四状态。 |
| 破损待采退 | 开启强制待核准；关闭后按系统匹配重新计算。 |

## 7. 验收

- [ ] 只有拍到票据后才能进入验货。
- [ ] 模拟识别可反复执行，行数不会固定在五行。
- [ ] 多票据下，品批按票据归属独立累积。
- [ ] 最新命中冲顶，旧行平滑下移，动画结束后类名清理。
- [ ] 追溯码管理、破损标记、码上放心资料兜底和搜索行为正确；列表内不存在无商品资料卡。
- [ ] 真实增加待核准或准入库时，右侧进度组件只播放一次对应反馈。
- [ ] 绿色、黄色、蓝色卡片分别对应准入库、待核准、已入库字段状态。
- [ ] 已入库追溯码再次识别时不新增、不冲顶、不触发命中动画、不改变进度，并提示“无法录入已入库追溯码”。
