# 实现、验证与模糊边界

## 1. 关键数据规则

1. `state.photos` 是票据图片当前集合；删除图片后必须先重建 `receiptPhotoId` 关联，再重算进度。
2. `receiveItems` 是验货页品批展示聚合；`codes` 为实录码，`expectedCodes` 为应录码集合。
3. `getApproveLineEntries` 生成核准卡投影；当前按用户后续明确口径逐个实录码生成数量为 1 的卡。
4. `approveDecisions` 表达当前核准去向；`confirmedPendingLineIds` 只负责把“留在待核准”卡排到队尾。
5. `getProgressGroups` 是三页、任务统计和状态明细的共同来源。任何页面不得存自己的四卡数字。
6. `inboundCompletedLineIds` 是已入库码集合；扫码前先检查，命中时拒绝新增。
7. 本期资料边界保证每个有效验货明细都有码上放心资料，因此 `scanEvents`、`receiveItems` 和核准投影均不保留“无资料/找不到商品”状态。
8. 核准辅助弹窗以 Figma 文件 `oJ9AkaKlnSG5qGslNzVk02` 的 `363:90` 为视觉来源；原始画布尺寸不直接落地，使用 `54vw/50vw + viewport max-height` 保持桌面比例。
9. `removedReceiptLineIds` 记录待验货页本次会话删除的 OCR 行投影；`inboundDrafts` 保存勾选入库后的数量、最终批次、系统行和追溯码分配快照。
10. 待核准批量提交、单条详情提交和工作台“放入准入库”共用 `isSystemMatchResolved` 拦截；没有系统单匹配时统一报错。

## 2. 关键事件顺序

### OCR 成功

```text
锁页 → 新增图片/OCR 行 → 按页排序 → 重建随货单关联
→ 重算系统核准 → 提交任务统计/最近操作时间 → 解锁 → 刷新 → “识别成功！”
```

### 删除票据

```text
勾选 → 二次确认 → 锁页 → 删除图片和对应 OCR 投影
→ 释放受影响关联 → 依次选择仍存在的下一候选 → 重核准 → 解锁刷新
```

### 扫码分组

```text
0.5 秒成组 → 锁页 → 重复码/已入库码拦截 → 匹配验货卡或要求人工选卡
→ 重算待验货/待核准/准入库 → 命中卡置顶 → 解锁
```

### 核准决策

```text
放入准入库：pending -1 / ready +1 / 当前卡飞出 / 下一条
留在待核准：pending 不变 / 当前卡移动队尾 / 无进度发光
提交入库：二次确认 → 校验系统单有效性 → 有效项生成入库草稿并 ready -N / inbound +N → 无效项重新对码核准 → A/B/C 回执
```

## 3. 验证基线

- 静态语法：`node --check app.js`。
- 页面尺寸：`1440×900` 主验收，`1280×800` 补充验收。
- 运行错误：浏览器控制台 error/warning 必须为空。
- 交互回归：任务日期、三页共享进度、票据批删确认、验货批删确认、扫码锁页、追溯码最后一条、候选 Enter 筛选、留待队尾、准入库迁移。

## 4. 原稿中已写但边界仍模糊

| 模糊点 | 文档现状 | 本轮处理 |
| --- | --- | --- |
| 验货明细唯一键与核准卡粒度 | 3.2 写 `bill_code + drug_ent_base_info_id + batch` 唯一；4.4.1 又说队列一一对应验货明细；用户后续明确要求逐件码卡 | 保留逐码核准卡，不按 Word 唯一键合并回品批卡 |
| 验货明细状态值 | 主表写 `0待核准/1准入库/2已入库`；验货 UI 表又写 `入库状态=1-已入库` | UI 分开表达明细核准状态与入库状态，不把两个枚举合并 |
| 系统核准结果术语 | 枚举是 `0无异常/1未录全/2有异常`，卡片规则文字出现“系统核准结果=待核准” | 以枚举为内部值，以“无需核准/待核准”为 UI 标签 |
| 追溯码蓝黄判断 | 一处写是否在应录码中；另一处写是否在实录码中 | 采用业务上可判定的“是否在应录码集合” |

| 删除的持久化方式 | 原稿写“删除图片/明细及所有数据”，未说明已产生入库或审计后物理删还是作废 | Demo 执行内存删除；生产实现需确认作废/审计策略 |

| O2O 映射失败 | 写了静态库优先、SPU 回退，但没写两者都失败时的 UI 和是否阻断 | 有关联时展示当前商品资料；两者都失败时显示“未关联到O2O商品资料”，不设置阻断 |
