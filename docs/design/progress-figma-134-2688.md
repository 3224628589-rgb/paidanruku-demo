# 入库进度组件：三页共享基线

- 共享基线：Figma `线上铺货` node `134:2688`，用于拍单、验货、核准三页。
- 核准主内容仍参考 node `232:5852`；node `231:5827` 只提供“提报异常”的视觉来源，不再覆盖共享组件尺寸或数据。
- 输出模式：`project-native-preview`，直接集成现有静态 Demo，不新增独立路由。

## 页面结构

```text
拍单  [取景框........................] [已拍票据：单列] [提报异常 + 共享四卡 + 动态轨]
验货  [扫码取景......................] [验货列表：滚动] [提报异常 + 共享四卡 + 动态轨]

核准  [待核准队列] [蓝色入库卡........................] [提报异常] [蓝轨]
                   [黄色商品资料 + 六图同屏.............] [已入库]   [绿轨]
                   [三方数据对比.........................] [准入库]   [黄轨]
                                                         [待核准]   [粉轨]
                                                         [待验货]
```

核准页蓝卡、黄卡、对比卡必须上下同宽同轴。六张商品图同屏展示，不横向滚动；三方数据对比位于黄卡下方。

## 核准页像素契约

`1280×800` 验收态（页面左侧仍包含步骤栏与待核准队列）：

| 元素 | 可见尺寸 / 位置 |
| --- | --- |
| 蓝色入库卡 | 随共享进度列占位自适应，保持 `980:320` 比例 |
| 黄色商品卡 | 与蓝卡同宽，保持 `980:237` 比例 |
| 三方对比卡 | 与蓝卡同宽，收起态保持 `980:145` 比例 |
| 提报异常主体 | 基础尺寸 `152×70px`；把手与主体共同形成顶部入口 |
| 四张状态卡 | 基础尺寸统一为 `152×200px` |
| 彩色轨道 | 基础宽度 `50px`；蓝、绿、黄、粉从上到下排列 |

拍单、验货、核准三页共用 `220×922px` 的同一进度组件；短屏统一按 `.84` 缩放，缩放原点固定为左上。

## 文案与动态数据

三页均按以下顺序显示：

- `提报异常`
- `已提交入库的清单 / 已入库{真实数量}`
- `核准后准备入库 / 准入库{真实数量}`
- `核准后发现异常 / 待核准{真实数量}`
- `仅拍单识别未验货 / 待验货{真实数量}`
- 按钮统一为 `查看全部`

三页一次渲染共用同一组 `getProgressGroups()` 结果；不允许按页面、步骤或任务 ID 覆盖数字。待验货保持 OCR 明细行计数，卡片数字与明细列表行数一致；已验商品按追溯码一件一卡进入准入库或待核准，核准队列必须逐卡逐行展示，不能按品批合并。蓝绿黄粉轨道严格按四卡真实卡片数量比例计算。

## 交互与状态

- “提报异常”在拍单、验货、核准三页渲染；点击后显示 `已标记：提报异常`。
- 四张状态卡和轨道段继续使用 `data-progress-open` 打开对应页内明细。
- 核准队列中的“放入准入库 / 留在待核准”仍是明细决策入口；状态卡内不增加决策按钮。
- “留在待核准”保持待核准数量不变，当前队列卡移动到队尾；不得飞入右侧待核准卡或触发轨道发光。
- 图片、扫码和商品数据均为本地 fixture，生产接入时应替换为服务端任务状态流。

## 验收

1. `1280×800` 与 `1440×900` 无页面级横向滚动，无卡片重叠或内容裁切。
2. 蓝卡、黄卡、对比卡同宽同轴，重要证据均在首屏。
3. 三页均显示提报异常，且组件结构、尺寸、间距完全一致。
4. 三页四卡数字和轨道比例来自同一份真实状态，切换步骤前后不变。
5. “留在待核准”只播放队列卡移动到队尾的动画，不触发右侧卡片或轨道发光。
6. 对同一品批连续扫码时，准入库或待核准逐卡增加；待验货仍按 OCR 明细行计数，只在该行余量归零时移除一行。
7. 核准队列一件一卡；`7 + 7 + 2` 件显示 `16` 行，核准一行只迁移一张卡。
