# 三期状态卡明细页设计与实现交付

> 本文件已按 2026-07-21 最新稿重写。完整逐条契约见 [PRD 对齐说明](prd-alignment/screen-contract.md)，版本变化见 [新旧需求差异](prd-alignment/version-diff-2026-07-21.md)。

## 交付范围

- 输出模式：`project-native-preview`。
- 需求来源：根目录《入库提效三期 拍单入库新.docx》4.5—4.9。
- 适用入口：三步工作台共享进度中的待验货、待核准、准入库、已入库四张状态卡。
- 快捷工具栏仍标注“需求评审下”，本轮不实现。

## 业务粒度

| 状态卡 | 列表结构 | 卡片数量口径 |
| --- | --- | --- |
| 待验货 | 随货单图片一级、OCR 随货单明细行二级 | 尚未发生实物命中的 OCR 行数 |
| 待核准 | 验货商品卡平铺 | 可独立核准的商品卡数；Demo 一码一卡 |
| 准入库 | 采购单一级、验货商品卡二级 | 当前准入库商品卡数 |
| 已入库 | 采购单一级、已提交商品卡二级 | 当前已入库商品卡数 |

包装数量、采购数量与状态卡数量是不同概念，均不得覆盖四卡数字。四张卡、任务列表和明细页统一读取 `getProgressGroups()`。

## 页面结构

```text
共享进度卡详情
├─ 待验货
│  └─ 图片页：页码/图片/供应商/业务单号/销售日期/发货日期
│     └─ OCR 行：商品/规格/准字/剂型/厂家/批次/包装数量/单价/验货标识
├─ 待核准
│  └─ 商品卡：商品资料/批次/应录与实录追溯码/当前异常项/核准详情
├─ 准入库
│  └─ 采购单：平台/单号/状态/供应商/平台单号/运单号
│     └─ 商品：最终入库批次/采购数量/入库数量/单价/核准详情
└─ 已入库
   └─ 与准入库同字段，核准详情严格只读
```

## 关键交互

| 页面 | 筛选 | 批量操作 |
| --- | --- | --- |
| 待验货 | 页码精准、通用名模糊、准字精准、只看未验货 | 勾选/全选当前结果/删除所选，删除前确认“确定删除？” |
| 待核准 | 药品名模糊、准字精准、异常项多选并集 | 勾选/全选当前结果/提交勾选项至准入库；无系统单匹配统一拦截 |
| 准入库 | 采购单精准、商品名模糊、准字精准 | 全局、采购单、商品三级选择；回退勾选项或提交勾选项入库 |
| 已入库 | 同准入库 | 无 mutation；详情仅返回 |

提交入库链路：

```text
勾选准入库商品
→ 二次确认“入库后库存将流入仓店可上架，是否继续？”
→ 复核系统单明细有效性
→ 有效项按实录追溯码数量和最终入库批次生成草稿并提交
→ 无效项返回待核准重新对码
→ 展示 A（采购单明细行）/B（入库数量）/C（无效行）回执
```

## 实现映射

| 职责 | 实现 |
| --- | --- |
| 状态投影与数字 | `getProgressGroups()`、`getProgressCountsSnapshot()` |
| 待验货两级页 | `renderUninspectedReceiptBucketListV2()` |
| 待核准页 | `renderPendingVerificationBucketList()` |
| 准入库/已入库两级页 | `renderPurchaseStatusBucketList()` |
| 勾选联动 | `bindBucketSelectionState()` |
| 批量准入库/回退 | `submitPendingEntriesToReady()`、`revertReadyEntriesToPending()` |
| 入库复核与草稿 | `submitReadyEntriesToInbound()`、`inboundDrafts` |
| 只读详情 | `renderApprovalBucketDetail()`、`renderApprovalEvidence(..., { readOnly: true })` |

## 验收结果

- `node --check app.js`、`git diff --check` 通过。
- 1440×900 与 1280×800 无页面级横向溢出。
- 待核准无系统单批量拦截、有效批量迁移、准入库回退、确认入库和 A/B/C 回执通过。
- 已入库详情仅有返回按钮；待验货筛选和批量删除通过。
- 拍单、验货、核准三页进度数字一致，切换步骤不改变状态。
- 浏览器控制台 warning/error 为空。
