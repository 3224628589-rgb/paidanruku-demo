# 智能入库 PC UI 设计规范

## 适用范围

本规范只约束当前桌面端 Demo。标准验收视口为 `1920 x 1080`，允许在常见笔记本宽度下收缩，但不再维护移动端、设备边框或竖屏布局。

## 页面骨架

| 页面 | 主布局 | 最重要信息 |
| --- | --- | --- |
| 任务入口 | 任务列表 + 新建入口 | 任务状态、票据数、追溯码数、异常数、进入动作 |
| 拍单 | 主取景框 + 右侧单列已拍票据 + 进度组件 | 当前票据画面与拍照动作 |
| 验货 | 左侧扫码取景 + 中间已录入品批 + 右侧进度组件 | 当前扫描画面、最近命中品批、品批列表 |
| 核准 | 左侧待核准队列 + 中部详情 + 右侧进度组件 | 当前异常、三方对比、核准决策 |
| 状态卡明细 | 单层平铺表格 + 右侧进度组件 | 业务唯一明细行、来源、差异与操作 |

规则：主要工作区占最多面积；任务标题、说明、装饰和重复边框不能与其竞争。页面不嵌套设备容器，不用页面级浮动卡片替代工作区。

## 尺寸与密度

- 外层应用为全宽桌面画布；内容使用稳定 grid，避免随文本增减改变列宽。
- 拍单票据位于取景框右侧，固定为单列纵向滚动，每行一张票据照片。
- 验货品批列表是可滚动的纵向工作列表，数据增长时增加行，不设置五行上限。
- 核准详情的上行放入库信息与美团商品资料；三方数据对比独占下行，便于横向比对。
- 待验货、待核准、准入库的明细页直接展示业务唯一行，不使用采购单卡片或采购单展开层。
- 状态明细页只保留一条紧凑搜索工具带；表头固定、表体纵向滚动，来源单据与供应商以内联字段呈现。
- 元素圆角不超过 `8px`，进度 Figma 卡片按源稿例外处理。

## 字体层级

| Token | 字号/行高 | 用途 |
| --- | --- | --- |
| `--font-display` | `24 / 32` | 关键数量、任务状态强调 |
| `--font-title` | `20 / 28` | 任务标题、核心提示 |
| `--font-subtitle` | `17 / 24` | 商品名、工作区标题 |
| `--font-body` | `14 / 22` | 按钮、表格主值、正文 |
| `--font-caption` | `12 / 20` | 字段名、元信息 |
| `--font-micro` | `11 / 16` | 标签、紧凑控件 |

同层信息只使用同一档字号，字间距保持 `0`。长商品名、规格和追溯码必须截断或换行，不可撑破卡片。

## Figma 入库进度组件

- 视觉源：Figma `线上铺货` node `134:2688`。
- 组件位于工作页右侧，标题为“入库进度查询”。
- 四卡顺序自上而下：已入库、准入库、待核准、待验货。
- 四张卡均为 `152 x 200px`，相邻卡片间隙 `13px`；右侧轨道宽 `50px`、内轨 `40px`。进度卡内不放核准操作。
- 轨道没有固定样例比例；每段实时高度为 `对应卡片数量 / 四卡数量总和`，四段之和恒为 `100%`。四卡总数为 `0` 时轨道为空。
- 卡片显示源稿的说明、图标和“查看全部”；数字与真实任务状态绑定，初始均为 `0`。
- 四卡分别按当前业务对象计数：待验货为 OCR 随货单明细行，待核准/准入库为对码核准明细，已入库为系统采购明细。四卡不是同一种实体的守恒迁移；数量增加时对应比例段增长并发光。

## 动效规范

- `bucket-impact`：真实数量增加时，目标进度卡轻微弹动，约 `0.92s`。
- `charging`：真实数量增加时，目标轨道段播放 `0.64s` 充能和边缘发光；1.05 秒后清除动效类。
- 待验货、待核准使用右侧推进的高光；准入库、已入库使用左侧推进的高光。
- 命中品批使用 `batchRushToTop` 冲到列表第一行；已有行用 FLIP 位移动画平滑下移。命中卡保留高亮约 2 秒，追溯码保留高亮约 1 秒。
- 所有动效只反馈数据变化，不得因切换页面或普通 render 自动播放。
