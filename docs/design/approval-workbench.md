# 核准页面 PC 设计说明

## 目标

核准页是异常入库明细的桌面工作台，不是移动端卡片流。用户应同时看见待处理队列、当前核对证据和入库进度，并能在不切换页面的情况下完成核准判断。

## 三列分工

| 区域 | 职责 | 不承担的内容 |
| --- | --- | --- |
| 左侧队列 | 搜索、切换待核准商品、显示队列密度 | 不展开复杂证据 |
| 中部详情 | 入库信息、随货单命中、美团商品、三方对比与编辑 | 不承担全局状态导航 |
| 右侧进度 | 提报异常、展示四类状态、打开对应明细 | 不覆盖核准详情或放置决策气泡 |

## 详情布局

- 中部详情严格按 Figma node `232:5852` 自上而下排列：蓝色入库信息卡、黄色商品资料与 6 图墙、三方数据对比。
- 三段同宽、同左边界，不再把蓝卡和黄卡左右压缩；异常字段优先，普通字段通过“展开全部字段”查看。
- 当前商品的名称、规格、状态和异常必须比候选切换、辅助字段更醒目。
- 核准完毕与核准待定是当前明细的命令，不再以漂浮气泡覆盖进度组件。

## 视觉取舍

- 蓝色表达当前工作和系统信息；橙/红仅表达异常；绿色仅表达准入库或完成。
- 队列保持紧凑，详情承担最大可视面积；避免卡片套卡片、无内容大留白和多余标题条。
- 右侧进度组件与拍单、验货共用同一结构：顶部是“提报异常”，下方依次为已入库、准入库、待核准、待验货，最右为四色分段轨。
- 三页进度组件基础尺寸统一为 `220×922px`；状态卡 `152×200px`、提报异常 `152×70px`、轨道宽 `50px`，短屏统一缩放。

## 验收要点

1. 当前明细、异常字段、三方对比和美团商品可在首屏同时扫描。
2. 点击队列、候选替换、编辑批次或追溯码后，详情刷新不改变三列结构。
3. “提报异常”与拍单、验货页一致，点击后反馈“已标记：提报异常”。
4. 右侧状态卡打开页内明细，不使用遮挡主工作区的大弹窗。
5. “留在待核准”将当前卡片移动到队尾，不改变进度数量、不触发右侧卡片或轨道发光。
6. `1440×900` 与 `1280×800` 均无页面级横向滚动，主内容、状态卡底部和轨道底部视觉对齐。
