# 掌店易智能入库 PC Demo

这是一个面向医药 O2O 前置仓店员的桌面端入库工作台原型。产品以“入库任务”为入口，任务内按拍单、验货、核准完成入库闭环。

## 本地预览

```bash
python3 -m http.server 4174
```

打开 `http://127.0.0.1:4174/`。入口页展示历史任务与“新建入库任务”；进入任务后才会进入三步工作台。

## 当前 PC 逻辑

1. **任务入口**：查看历史入库任务，或新建任务。任务卡展示步骤、票据数、追溯码数、异常数和最近更新时间。
2. **拍单**：高拍仪画面是主区域；已拍票据以横向单行、横长竖短的缩略图列在下方。拍照或上传会新增票据并触发待验货进度反馈。
3. **验货**：左侧为扫码画面，右侧为可滚动的已录入品批。每张票据可形成自己的品批集合；模拟识别持续增加行数。命中品批冲到列表顶部，原卡片平滑下移。
4. **核准**：左侧待核准队列、中部核对详情、右侧 Figma 进度组件。核准完成进入准入库，待定保留在待核准。
5. **入库进度**：所有工作页右侧均展示 Figma 参考组件。四张卡的文案、尺寸和轨道比例来自 Figma；卡片点击进入对应状态明细。真实数量增长时才播放卡片弹动和轨道发光。

## 需求准则

本 Demo 的业务与交互第一准则是根目录最新稿 [《入库提效三期 拍单入库新》](入库提效三期%20拍单入库新.docx)；[旧稿](入库提效三期%20拍单入库.docx)仅用于版本对比。`docs/product/` 下的文档用于解释当前实现和记录后续已确认口径；若与最新 Word 冲突，必须先登记冲突，不能用派生稿静默覆盖。

本轮逐条对照与验收入口见 [PRD 对齐交付说明](docs/design/prd-alignment/README.md)。

## 维护规则

- 页面或交互变化时，先更新 `docs/product/workflow-and-states.md` 与对应页面规格，再同步 UI 规范、PRD 和 QA。
- 当前仅验收 PC；不再维护移动端、设备外框或竖屏布局要求。
- 静态资源通过 `index.html` 中的版本参数加载。改动 CSS/JS 后同步更新版本参数，避免部署缓存命中旧页面。
